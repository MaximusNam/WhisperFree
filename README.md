# WhisperFree

Голосовой ввод для Windows: зажал клавишу, сказал, отпустил — текст появился там,
где стоял курсор.

## Как это выглядит

```
зажал правый Ctrl  →  внизу экрана плашка «слушаю»
сказал             →  «поставь докер на сервер и перезапусти контейнер»
отпустил           →  Поставь Docker на сервер и перезапусти контейнер.
```

Работает в любом окне: браузер, мессенджер, Word, терминал с Claude Code.

---

## Возможности

- Диктовка удержанием правого Ctrl — текст вставляется туда, где стоял курсор, в любом окне Windows.
- Распознавание через Groq, модель `whisper-large-v3-turbo`: 204–336 мс на запрос на живых диктовках, средняя длина которых 9.2 секунды речи (замерено, август 2026).
- Правка моделью-редактором `openai/gpt-oss-120b`: падежи, пунктуация, согласование, 293–480 мс.
- Словарь терминов с регулярками — `докер` во всех падежах становится `Docker`, правится в одном файле.
- Пре-ролл 250 мс: запись начинается до нажатия клавиши, поэтому первый слог не срезается.
- Ключ API читается только из `.env` или переменной окружения, в `config.toml` он не попадает никогда.
- История расшифровок: Ctrl+Alt+V вставляет последнюю заново, Ctrl+Alt+H открывает окно с поиском.
- Автоподбор клавиши вставки: в терминалах вместо Ctrl+V уходит Ctrl+Shift+V, буфер обмена восстанавливается.
- Стоимость одной диктовки на платном тарифе — $0.000201, около $0.60 в месяц при сотне диктовок в день.

## Почему я ушёл с Wispr Flow

Я платил за Wispr Flow $15 в месяц, и деньги были наименьшей из проблем. Продукт
хороший, но три вещи мешали каждый день: подписка, ручное ведение словаря и то,
что распознавание регулярно не понимало сказанное. Последнее — мой личный опыт, а
не измеренное сравнение: сравнительных тестов точности я не проводил и приводить
их не буду.

Со словарём всё нагляднее. В Wispr Flow есть Dictionary, и его приходится
заполнять руками, слово за словом, иначе термины калечатся: `Gemini` превращается
в «Джемини», `Docker` — в «Докер». В WhisperFree словарь замен лежит в
`config.toml` и понимает регулярные выражения: одна строка `re:\bдокер\w*` =
`"Docker"` закрывает все падежи и дефисные написания сразу. Сверху идёт проход
модели-редактора, а словарь применяется уже после него — последнее слово в
терминологии остаётся за вашим файлом, а не за моделью.

Всё, что я могу утверждать про скорость и расходы, — это собственные замеры на
живых запросах, август 2026: распознавание 204–336 мс, правка 293–480 мс, средняя
диктовка 9.2 секунды речи и 104 символа на выходе. Бесплатный тариф Groq на тот же
момент давал 2000 запросов распознавания и 1000 запросов к чат-модели в сутки —
потолок получается около 1000 диктовок в день и упирается в правку. Лимиты
провайдер меняет; актуальные показывает `limits.bat`, он читает их из заголовков
ответа API.

| | WhisperFree | Wispr Flow |
|---|---|---|
| Цена | бесплатный тариф провайдера, на платном $0.000201 за диктовку | $15 в месяц |
| Словарь терминов | файл `config.toml`, регулярки на все падежи, поверх — модель-редактор | Dictionary, заполняется вручную по слову |
| Где хранится ключ | ваш `.env` или переменная окружения, в конфиг не пишется | своего ключа нет, запросы идут через сервис |
| Открытый исходный код | да, лицензия MIT | нет |

## Быстрый старт

**1. Окружение**

```bash
python -m venv .venv
```

```bash
.venv\Scripts\python -m pip install -e .
```

**2. Ключ провайдера**

Заведите ключ на [console.groq.com/keys](https://console.groq.com/keys) — там есть
бесплатный тариф и карта не нужна. Скопируйте `.env.example` в `.env` и вставьте ключ:

```
GROQ_API_KEY=gsk_ваш_ключ
```

Ключ читается только из `.env` или переменной окружения. В `config.toml` он не
попадает никогда.

**3. Проверка**

Достаточно запустить **`check.bat`** двойным щелчком. Он покажет, найден ли
ключ, откроет микрофон, запишет три секунды, отправит их провайдеру и напечатает,
что распозналось.

Если микрофон не тот, **`devices.bat`** покажет список. Имя оттуда вписывается
в конфиг:

```toml
[audio]
device = "Logitech StreamCam"
```

Имя надёжнее индекса: индексы съезжают при подключении и отключении устройств.
Достаточно куска имени, регистр не важен. Одна железка обычно видна сразу в
четырёх звуковых API (MME, DirectSound, WASAPI, WDM-KS) — берётся та, что
относится к API по умолчанию.

**4. Проверка вставки**

Механика вставки в разных приложениях разная, поэтому её стоит прогнать по всем
окнам, где вы собираетесь диктовать. Запустите **`paste-test.bat`**: даётся пять
секунд, чтобы переключиться в нужное окно, после чего туда вставляется тестовая
фраза, а в консоли печатается, какое окно распознано и какой клавишей вставлялось.

Пройдите так по блокноту, адресной строке браузера, терминалу с Claude Code,
Telegram или VS Code и полю в Word.

**5. Запуск**

`run.vbs` — молча, значок появится в трее. `run.bat` — с консолью и подробным логом.

Чтобы стартовало при входе в систему: значок в трее → «Запускать при входе».
Программа кладёт `WhisperFree.vbs` в папку автозагрузки — открыть её можно
командой `shell:startup` в проводнике, а выключить автозапуск достаточно
удалением этого файла.

Папка автозагрузки выбрана вместо привычного ключа реестра `HKCU\...\Run`
намеренно. Реестр умеют виртуализировать: процесс в контейнере приложения
пишет в свой куст, читает оттуда же и выглядит вполне довольным, а настоящий
сеанс пользователя записи не видит. Файл в автозагрузке видно глазами.

## Клавиши

| Клавиша | Что делает |
|---|---|
| **Правый Ctrl** (удерживать) | Записать и вставить |
| **Ctrl+Alt+V** | Вставить последнюю расшифровку заново |
| **Ctrl+Alt+H** | Открыть окно истории |

Правый Ctrl выбран потому, что его почти никто не использует, а `Ctrl+Win` уже
занят Wispr Flow. Поменять можно в `[hotkeys]`.

Не ставьте в `dictate` правый Shift: он нужен для заглавных букв, и каждая
заглавная запускала бы запись.

## Если текст не вставился

Вставка в чужое окно принципиально ненадёжна: окно могло потерять фокус,
приложение могло съесть Ctrl+V, поле могло оказаться нередактируемым. Проверить,
вставилось ли на самом деле, в Windows в общем случае нельзя — поэтому программа
не пытается ловить провал, а делает его безболезненным.

- **Текст попадает в буфер обмена до попытки вставки.** Даже если не вставилось —
  работает обычный Ctrl+V руками.
- **Каждая расшифровка пишется в журнал** `%APPDATA%\WhisperFree\history.jsonl`
  вместе со временем, языком, длительностью и именем приложения-получателя.
  Запись делается **до** вставки: даже падение на вставке ничего не теряет.
- **Ctrl+Alt+V вставляет последнюю расшифровку.** Нажатия подряд идут вглубь:
  первое даёт последнюю, второе предпоследнюю, и так далее. Пауза в три секунды
  сбрасывает счётчик обратно на свежую.
- **Трей → «Последние расшифровки»** — десять последних, клик вставляет.
- **Ctrl+Alt+H** открывает окно истории с поиском. Неудачные попытки подсвечены
  красным — обычно ищут именно их.
- **Ошибка всегда видна.** Плашка внизу экрана краснеет и пишет, что случилось.
  Молчаливая потеря продиктованного абзаца — худший из возможных исходов, поэтому
  её нет.

Буфер обмена возвращается к прежнему содержимому через 300 мс после вставки.
Если хотите, чтобы последняя расшифровка всегда оставалась в буфере, как в
Wispr Flow, поставьте `restore_clipboard = false`.

## Русский вперемешку с английским

Это главная сложность: модели норовят записать `Gemini` как «Джемини», а `Docker`
как «Докер». Работают три слоя, каждый настраивается.

**1. Затравка для модели** — `[language].prompt_ru`, а для английского
`prompt_en`. Строка с образцом пунктуации и вашими терминами латиницей. Модель воспринимает её как пример желаемого формата.
Добавляйте туда свои термины, лимит — 224 токена.

**2. Словарь замен** — `[postprocess.replacements]`. Детерминированно, мгновенно
и бесплатно добивает то, что не вытянула затравка:

```toml
"джемини" = "Gemini"
"пул реквест" = "pull request"
```

Регистр не важен, совпадение идёт по границам слов. Заглавная буква в начале
предложения сохраняется: «Коммит готов» станет «Commit готов».

Для падежей есть регулярки — ключ с префиксом `re:`:

```toml
"re:\\bдокер\\w*" = "Docker"   # докера, докером, докеру
```

**3. Отдельная клавиша для английского.** Задайте `dictate_alt` (например
`scroll_lock`) — эта клавиша будет диктовать на языке из `language.alt`.
В поставляемом конфиге она выключена: `dictate_alt = ""`. Пока строка пустая,
вторая клавиша не регистрируется вовсе, и `language.alt` вместе с `prompt_en`
ни на что не влияют.

Секция `[language]` целиком — это четыре ключа:

| Ключ | Смысл |
|---|---|
| `main` | Язык основной клавиши диктовки, по умолчанию `ru` |
| `alt` | Язык второй клавиши, по умолчанию `en`. Работает только при заданном `dictate_alt` |
| `prompt_ru` | Затравка для русского |
| `prompt_en` | Затравка для английского |

Затравка выбирается по языку диктовки: `prompt_en` уходит в запрос, когда язык
`en`, во всех остальных случаях — `prompt_ru`.

## Правка текста моделью

Распознавание выдаёт слова, но не грамматику: падежи не согласованы,
пунктуации нет, окончания угаданы на слух. Включите `[refine].enabled = true`,
и перед вставкой текст пройдёт через быструю модель.

```
было : запустил диктую пробую запись эти слова набраны уже из нового
       единственное что я хотел бы чтобы он еще проверял
стало: Запустил диктую, пробую запись. Эти слова уже набраны из нового.
       Единственное, что я хотел бы, чтобы он ещё проверял...
```

Замеры на Groq, на прогретом соединении: **в среднем 293 мс**. Общий цикл
получается около 1.3 с. У меня на Wispr Flow тот же цикл занимал 2–4 с,
но это моё впечатление от работы с ним, а не измеренное сравнение.

**Модель выбрана по замерам.** `openai/gpt-oss-120b` с `reasoning_effort = "low"`
даёт лучшее качество и не правит лишнего: фразу «Раз, два, три, проверка.» она
оставляет как есть, тогда как 20b без нужды меняет запятую на тире. Модели
`qwen` вываливают в ответ свои рассуждения и не годятся вовсе.

**Главный риск — не качество, а самовольство.** Модель может ответить на текст
вместо того, чтобы его исправить, дописать от себя или выбросить кусок.
Поэтому результат проверяется, и при любом сомнении берётся исходный вариант:

- ответ пустой или в нём остались следы рассуждений;
- текст вырос больше чем в `max_growth` раз — значит, модель начала отвечать;
- текст усох вдвое — значит, часть сказанного потерялась;
- запрос не прошёл или не уложился в `timeout_s`.

Потерять продиктованное хуже, чем оставить его негладким. Если правка всё же
исказила смысл, исходный текст лежит рядом в истории — окно `Ctrl+Alt+H`.

**Словарь замен применяется ПОСЛЕ правки**, чтобы последнее слово в терминах
осталось за вашим конфигом, а не за моделью.

## Сколько это стоит

Цифры ниже посчитаны не по прикидкам, а по замерам на живых диктовках:
средняя длина **9.2 секунды и 104 символа**, расход правки **218 + 96 токенов**.

**Одна диктовка — 0.02 цента:**

| | за диктовку |
|---|---|
| Распознавание (`whisper-large-v3-turbo`, $0.04/час) | $0.000111 |
| Правка текста (`gpt-oss-120b`, $0.15/$0.60 за млн токенов) | $0.000090 |
| **Итого** | **$0.000201** |

Правка стоит почти столько же, сколько распознавание — при её отключении
расходы падают примерно вдвое.

**В месяц:**

| Диктовок в день | Это примерно | С правкой | Без правки |
|---|---|---|---|
| 20 | 3 мин речи | $0.12 | $0.07 |
| 50 | 8 мин речи | $0.30 | $0.17 |
| 100 | 15 мин речи, ~10 тыс. знаков | $0.60 | $0.33 |
| 200 | 31 мин речи, ~20 тыс. знаков | $1.21 | $0.67 |
| 500 | 77 мин речи | $3.02 | $1.67 |
| **Wispr Flow** | — | **$15.00** | **$15.00** |

Чтобы дойти до $15 в месяц, нужно диктовать **больше шести часов в день без
выходных**. На практике счёт закрывается меньше чем долларом.

**Где переплата.** У Groq минимальный тарифицируемый отрезок — 10 секунд.
Реплика на 3 секунды тарифицируется как десятисекундная, то есть втрое дороже
своей длины. Три коротких реплики стоят как одна тридцатисекундная — длинными
фразами диктовать выгоднее, хотя на таких суммах это уже вопрос принципа.

Текущий расход виден в трее: количество и сумма за сегодня и за месяц, плюс
разбивка на распознавание и правку.

Нужно качество распознавания повыше — `model = "whisper-large-v3"` ($0.111/час,
ошибок примерно на четверть меньше, но медленнее).

## Другой провайдер

Endpoint любой OpenAI-совместимый, поэтому смена провайдера — это три строки
в `[provider]`, без правки кода:

```toml
# OpenAI
base_url = "https://api.openai.com/v1"
model = "gpt-4o-transcribe"
api_key_env = "OPENAI_API_KEY"
```

Так же подключаются прокси и локальные сервера. Если `api.groq.com` не открывается
из вашей сети, программа скажет об этом прямым текстом («доступ запрещён (403) —
возможно, провайдер недоступен из вашей сети»), и достаточно поменять `base_url`.

## Настройки, о которых стоит знать

Конфиг ищется в двух местах, в таком порядке:

1. **`config.toml` рядом с программой** — переносимый режим. Тогда там же
   оказываются `history.jsonl`, `logs/` и `audio/`, и всю папку можно
   переносить целиком.
2. `%APPDATA%\WhisperFree\config.toml` — если файла рядом нет.

Переносимый режим стоит предпочитать, и не только ради удобства. `%APPDATA%`
умеют подменять: приложения из Microsoft Store и программы в MSIX-контейнерах
видят вместо `C:\Users\<имя>\AppData\Roaming` свой `LocalCache`, **печатая при
этом ровно тот же путь**. Правка конфига, сделанная из такой программы, до
обычного запуска не доходит, а выглядит это как «настройки игнорируются».
Файл рядом с программой такой подмены не знает.

Полный образец с комментариями — в `config.example.toml`. Открыть текущий
можно из трея.

| Параметр | Смысл |
|---|---|
| `[audio].device` | Микрофон. Пусто — системный по умолчанию, иначе часть имени или индекс из `devices.bat` |
| `[audio].preroll_ms` | Сколько звука **до** нажатия попадает в запись. 250 мс спасают первый слог |
| `[audio].min_seconds` | Короче — считается случайным нажатием и игнорируется |
| `[audio].silence_peak` | Порог тишины 0..1. Ниже него запрос не отправляется. Фон микрофона ~0.010, речь 0.1–0.7 |
| `[audio].hold_open` | `false` отпускает микрофон между диктовками — значок в трее гаснет, но пропадает пре-ролл |
| `[inject].paste_overrides` | Клавиша вставки для конкретных программ. Для терминалов — `ctrl+shift+v` |
| `[inject].method` | `unicode` вместо `clipboard`, если буфер трогать нельзя. Медленнее |
| `[history].keep_audio` | Хранить аудио последних диктовок, чтобы перераспознать без переговаривания |
| `[hotkeys].suppress` | Прятать клавишу диктовки от приложений. Работает только для выделенных клавиш |

## Файлы рядом с программой

Всё, что запускается двойным щелчком, лежит в корне проекта. Эти файлы берут
`.venv` рядом с собой и, если окружения нет, прямо об этом пишут; единственное
исключение — `sound.bat`, ему Python не нужен вовсе.

| Файл | Что делает |
|---|---|
| `run.vbs` | Тихий запуск: консоли нет, значок появляется в трее |
| `run.bat` | То же самое с консолью и подробным логом |
| `check.bat` | Проверяет ключ, микрофон и провайдера: пишет три секунды и печатает, что распозналось |
| `devices.bat` | Список микрофонов — имя оттуда идёт в `[audio].device` |
| `calibrate.bat` | Измеряет фон микрофона за три секунды тишины и сам записывает подобранный `[audio].silence_peak` в конфиг |
| `paste-test.bat` | Даёт пять секунд на переключение в окно, вставляет туда тестовую фразу и печатает, чем вставлял |
| `limits.bat` | Остаток лимитов тарифа, прочитанный из заголовков ответа API |
| `sound.bat` | Открывает классическую панель «Звук» на вкладке «Запись»: ползунок громкости микрофона и Microphone Boost живут там, а не в современных «Параметрах» |
| `diag.bat` | Печатает размер, время и sha256 того `config.toml`, который открыл именно этот процесс |
| `build.bat` | Собирает самостоятельную папку `dist\WhisperFree` |

Про `calibrate.bat` стоит помнить, что порог тишины зависит не только от
микрофона, но и от его громкости в системе: подняли ползунок — фон вырос,
и прежний порог перестал его отсекать. Поэтому порог лучше не угадывать,
а перемерять после каждой возни с громкостью.

`diag.bat` нужен для одного вопроса: какой файл конфига читает программа на
самом деле. Запустите его двумя способами — двойным щелчком из проводника и
из своего терминала — и сравните строки sha256. Разные хеши означают, что
процессы открывают разные файлы: так ловится подменённый `%APPDATA%`,
о котором сказано выше.

## Если что-то не так

**SmartScreen или антивирус ругаются.** Ожидаемо: перехват клавиатуры использует
тот же Win32 API, что и кейлоггеры, а сборка не подписана.

**Не работает поверх окна, запущенного от администратора.** Ограничение Windows:
хук процесса без прав администратора не видит события в окнах с правами. Лечится
только запуском WhisperFree от администратора.

**Перестало реагировать после сна.** Не должно: сторожевой поток ловит
пробуждение по расхождению настенных и монотонных часов и пересобирает хук.
Если всё же случилось — в логе будет строка «пересобираю хук клавиатуры»,
приложите её к отчёту.

**В терминале вставляется не туда или ничего.** Добавьте свой терминал в
`[inject.paste_overrides]` с `ctrl+shift+v`. Готовые записи уже есть для
Windows Terminal, conhost, mintty и PuTTY.

**«Тишина: уровень ниже порога».** В сообщении и в логе указан измеренный
уровень и порог — по ним сразу видно, что делать.

- Уровень около нуля (меньше 0.001) — звука нет вообще. Смотрите в логе строку
  «настройки»: если там «микрофон=системный по умолчанию», берётся системный
  микрофон, а он далеко не всегда тот, который нужен. Впишите свой через
  `devices.bat`.
- Уровень заметный, но ниже порога (скажем, 0.015 при пороге 0.02) — микрофон
  работает, но тихий. Прибавьте громкость в параметрах звука Windows
  (`sound.bat` открывает нужную вкладку) или уменьшите `[audio].silence_peak`.
  Порог не обязательно подбирать руками: `calibrate.bat` три секунды слушает
  тишину, измеряет фон вашего микрофона, берёт втрое больше и записывает
  результат в конфиг сам.

`check.bat` печатает и уровень, и порог, и что именно из этого следует —
начинайте с него, но **говорите** в те три секунды, что он слушает.

**Значок микрофона в трее горит постоянно.** Так и задумано: поток микрофона
держится открытым, чтобы работал пре-ролл — те 250 мс до нажатия клавиши,
без которых срезается первый слог. Если это мешает, поставьте
`[audio].hold_open = false`: устройство будет заниматься только на время
диктовки, но пре-ролл пропадёт и начало фразы может теряться.

**Текст вставляется дважды.** Значит запущены две копии. Начиная с этой версии
второй экземпляр не стартует и сообщает об этом, но старые процессы могли
остаться — проверьте диспетчер задач на `python.exe` с `whisperfree` в командной
строке.

**Ctrl+C с правым Ctrl превращается в букву «c».** Такого быть не должно —
модификаторы намеренно не подавляются, даже при `suppress = true`. Если увидели,
это баг, в логе будет видно, какая клавиша подавляется.

Логи: `%APPDATA%\WhisperFree\logs\whisperfree.log`, открываются из трея. Каждая
диктовка пишет строку с таймингами по стадиям — сразу видно, что тормозит.

## Сборка в самостоятельный exe

Для повседневной работы не нужна — `run.vbs` и автозапуск работают и так.
Пригодится, чтобы перенести программу на другую машину, где нет Python.

```bash
build.bat
```

Получается папка `dist\WhisperFree` (74 МБ), которую можно перенести целиком.
Ключ кладите в `.env` рядом с `WhisperFree.exe` — программа ищет его и там,
а не только в рабочем каталоге. При запуске из папки автозагрузки рабочий
каталог задаёт сам `WhisperFree.vbs`: он выставляет `shell.CurrentDirectory`
в папку с exe перед запуском. Но стоит запустить exe ярлыком, из терминала
или чужим скриптом — и рабочим каталогом окажется что угодно, вплоть до
`System32`. Файл рядом с exe находится в любом случае.

Сборка проверена и запускается. Два подводных камня уже обойдены и описаны
в `build.bat` и `whisperfree.spec`, чтобы не наступить на них снова:

- PyInstaller в venv не находит Tcl/Tk и **молча выбрасывает tkinter** из
  сборки — exe падает на `ModuleNotFoundError: tkinter`. Поэтому `build.bat`
  выставляет `TCL_LIBRARY` и `TK_LIBRARY` до запуска сборки.
- Точкой входа указан `whisperfree_app.py`, а не `whisperfree/__main__.py`:
  PyInstaller запускает указанный скрипт как `__main__` без пакетного
  контекста, и относительные импорты внутри пакета падают.

## Как это устроено

```
whisperfree/
  __main__.py        точка входа, раскладка по потокам
  audio.py           всегда открытый поток микрофона, кольцевой буфер пре-ролла
  hotkey.py          хук клавиатуры, независимость от раскладки, сторож на сон
  inject.py          буфер обмена и SendInput, выбор клавиши вставки по программе
  providers/         адаптер к OpenAI-совместимому endpoint
  postprocess.py     словарь замен, отсев галлюцинаций на тишине
  history.py         журнал расшифровок и повторная вставка
  overlay.py         плашка состояния поверх всех окон
  tray.py            значок, меню, счётчик расходов
```

Потоки: главный занят циклом Tk, хук клавиатуры живёт в своём и обработчики в нём
обязаны быть мгновенными, вся долгая работа уходит в рабочий поток, трей и
микрофон крутятся отдельно.

Тесты. `pytest` лежит в extras `dev`, поэтому его сначала нужно поставить —
установка из «Быстрого старта» его не тянет:

```bash
.venv\Scripts\python -m pip install -e ".[dev]"
```

```bash
.venv\Scripts\python -m pytest -q
```

## Замеры

Что уже проверено на машине, где это писалось (i7-4820K, Windows 10 Pro 19045):

- **FLAC вместо WAV — на 78% меньше** данных на отправку (5 секунд звука:
  34.7 КБ против 156.3 КБ), кодирование без потерь, бит в бит. Это напрямую
  вычитается из задержки.
- **Буфер обмена** переживает кириллицу, многострочный текст, «ёлочки», тире и
  эмодзи вне BMP; прежнее содержимое возвращается.
- **Отсечка тишины** работает: пиковый уровень пустой записи 0.0000 при пороге
  по умолчанию 0.02.
- **Определение активного окна** работает — программа видит имя exe, чтобы
  выбрать клавишу вставки и записать в историю, куда ушёл текст.
- **Groq отвечает за 270–340 мс** на отдельном двухсекундном фрагменте, вместе
  с сетью. Это стендовый замер на одном коротком файле; разброс на живых
  диктовках, где средняя длина 9.2 секунды речи, — 204–336 мс, он приведён
  в «Возможностях». С учётом кодирования и вставки цикл укладывается в целевые
  1.5 с с большим запасом. Wispr Flow, когда я им пользовался, на тот же
  цикл тратил 2–4 с — это личное наблюдение, а не замер на стенде.
- **383 автотестов** проходят, включая сквозной прогон конвейера с подставным
  провайдером: запрос уходит с нужным языком и затравкой, словарь замен
  применяется до вставки, запись попадает в историю раньше вставки, а после
  провала вставки текст достаётся хоткеем.

Что нужно замерить уже в работе и вписать сюда:

- задержку по стадиям из лога — цель меньше 1.5 с от отпускания клавиши до вставки;
- реальный расход за день по счётчику в трее, сверить с оценкой $0.40–1.50/мес;
- долю техтерминов, записанных латиницей, до и после словаря замен: продиктуйте
  двадцать фраз с терминами и посчитайте.

Два бага эти проверки уже поймали:

- Размер буфера обмена считался в кодовых точках вместо единиц UTF-16, из-за
  чего эмодзи вставлялся обрезанным до половины суррогатной пары. На обычном
  тексте это никогда бы не проявилось.
- Фильтр галлюцинаций ловил конкретные фамилии из списка. На первом же реальном
  запросе Groq выдал на чистом тоне «Редактор субтитров А.Семкин Корректор
  А.Егорова» — фамилии оказались новые, и текст прошёл бы насквозь. Теперь
  ловится шаблон целиком, а не перечень имён.
